# Инструкция для студента: как выполнять и сдавать домашнее задание

## 1. Что дано

- `include/` — **контракт на C**: интерфейсы, которые вы реализуете.
  Комментарии `TODO(student)` описывают ожидаемое поведение. **Менять эти
  файлы нельзя** — CI отклонит такой MR.
- `src/` — заглушки без логики. **Здесь и только здесь** вы пишете решение,
  **на чистом C** (`.c`-файлы).
- `tests/` — тесты на C++ с GTest: MAC <-> каноническая строка. C++ используется
  только здесь, как готовый фреймворк (ASSERT/EXPECT, фикстуры). Тесты **можно
  и нужно читать** (это точная спецификация поведения), **нельзя менять**.
- `CMakePresets.json` — два пресета: `debug` (обычная сборка) и `asan`
  (сборка с ASan + UBSan — так же, как в CI).

## 2. Локальная работа

```bash
git clone <репозиторий задачи> && cd <директория репозитория задачи>

cmake --preset debug                # конфигурация (первый раз скачает GTest)
cmake --build --preset debug        # сборка
ctest --preset debug                # все тесты; на заглушках они красные
```

Полезное:

```bash
ctest --preset debug -R <TestName>      # только тесты с нужным именем
ctest --preset debug --rerun-failed     # только упавшие
./build/hw_tests --gtest_filter=*       # напрямую запустить бинарь тестов
```

Санитайзеры (проверьте перед сдачей — CI гоняет то же самое):

```bash
cmake --preset asan
cmake --build --preset asan
ctest --preset asan
```

Если ASan/UBSan нашли проблему — в логе будет стек. `detect_leaks=1` включён:
утечки памяти приводят к падению тестов.

## 3. Порядок решения

1. Прочитайте контракт в `include/` и тесты в `tests/` — сначала поймите
   поведение, потом пишите код.
2. Реализуйте логику **на C** в `src/`.
   Новые файлы добавляет преподаватель в `CMakeLists.txt` по запросу —
   сам файл изменять нельзя.
3. Добейтесь зелёных `ctest --preset debug` и `ctest --preset asan`.

## 4. Сдача (MR)

```bash
git checkout -b solution-<student-name>
git add -A && git commit -m "<Commint message>"
git push -u origin solution
```

Далее на GitHub откройте pull request в `main` (шаблон MR заполнит чек-лист).
CI запустит три проверки:

| Проверка                    | Значение                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `protected files untouched` | вы не меняли `include/`, `tests/`, `CMakeLists.txt`, `CMakePresets.json`, `.github/`, `docs/`, `README.md` |
| `build & ctest`             | сборка и тесты на gcc и clang                                                                              |
| `ASan + UBSan`              | тесты под санитайзерами                                                                                    |

**MR сливается только при всех зелёных проверках** (и при необходимости —
после approve преподавателя). Красная проверка = исправляйте и пушьте снова,
пайплайн перезапустится автоматически.

## 5. Частые проблемы

- **Первый `cmake --preset debug` висит/не качает GTest** — нужен доступ к
  github.com. Альтернатива: `apt install libgtest-dev` (нужна версия ≥ 1.14),
  CMake подхватит системный GTest сам.
- **«Changes to protected files are not allowed» в CI** — вы случайно
  отредактировали защищённый файл. Восстановите его:
  `git checkout origin/main -- <файл>`.
- **Тест падает, хотя «всё работает»** — перечитайте контракт в комментарии
  `TODO(student)` и тест именно на этот сценарий: тест — эталон, а не код в
  вашем опыте. Если проблема не решается - напишите преподавателю с ссылкой на
  упавший pipline.
- **ASan ругается на ваш код в тестах** — так и задумано: выравнивайте
  работу с памятью (выходы за границы буфера, use-after-free, утечки).
- **Хочу добавить файл в сборку** — попросите преподавателя: он добавит его
  в `CMakeLists.txt` (файл защищён).
